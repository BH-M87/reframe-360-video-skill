# 验证、隐私与交付

## 检查工具的边界

| 工具 | 能证明 | 不能证明 |
|---|---|---|
| probe_media.py | 在注明能力范围内的轨道/时轴 inventory | IMU可用、主镜头内容、完整封面枚举 |
| validate_imu.py | 配置的 gyro/可选四元数列的数值、时标、覆盖及表示检查 | 加速度/rig已验证、gyro与图像已配准、镜头正确、成片稳定 |
| check_v360_state.py | 当前 FFmpeg 对重复绝对姿态的实际行为 | 用户素材取景、镜头标定或防抖效果 |
| verify_export.py | 实际完整解码和显式交付约束 | 本人完全不出现、菜名正确、运镜自然、果冻消失 |
| rolling_shutter.py | 给定 model8/姿态/读出输入下的映射、覆盖及注明范围的数值误差 | 读出方向/同步已正确、视觉已改善或镜头模型适用于其它相机 |
| compare_video_streams.py | 两文件指定视频流的压缩包、规范化时序和显示元数据等价 | 音频/新容器合格，或旧视觉审阅覆盖了未看过的帧 |

probe 的 stdlib 只看轨道样本，covr 等元数据封面可能未枚举。零时基、零delta、空视频轨或unsupported结构不能进入“已可处理主视频”结论。

所有报告使用新路径。不要把其它媒体、既有报告、源/输出的硬链接或符号链接当报告目标。检查源与交付不是同一文件；音频参考不能指向输出自身来自证一致。

## 先定义本次验收

记录源区间、输出速度、目标画幅/尺寸、色彩、音频处理、字幕依据和隐私范围。帧数来自当前时轴/裁切计划；不用历史素材的固定数字。VFR→CFR必须明确记录映射，不能把重复/丢帧当稳定效果。

典型可分享 MP4 为 H264/yuv420p、AAC、square pixels、faststart；按实际平台/用户交付配置编码，并区分 HDR/SDR。发现 HDR 不静默当 BT709套用。

## 标准化 IMU 检查

列名、单位和四元数顺序必须显式匹配。例如（以下列名是工具默认接口，不是源厂商字段）：

    python3 "$SKILL_DIR/scripts/validate_imu.py" "$VIDEO_WORK/imu.csv" --gyro-units rad/s --quaternion-csv "$VIDEO_WORK/quaternions.csv" --report "$VIDEO_WORK/imu-check.json"

- 可用列适配参数；--coverage-start/--coverage-end 声明视频所需时间。若逐行读出需要额外覆盖，也纳入要求。
- CSV中的额外列不自动成为检查对象；加速度的单位、物理方向、重力估计和 rig 仍由相应适配器单独验证。
- max-gap 是当前任务允许的缺口，默认仅作起点，按实际采样率设置；小片段通过不表示全片覆盖。
- q/-q 符号翻转会给出表示警告；严格要求连续分量时用 --require-continuous-quaternion-sign。不得原地改原始 CSV。
- 只有已知 gyro 和四元数处于同一体坐标、同一时轴且四元数为 body-to-world 时才使用 --gyro-quat-same-frame。描述性相关很高也不能代替图像同步验证。
- 未提供姿态时 orientation 维持 unverified，不能把数值正常提升为“惯性稳像已验证”。

## 真实画面质量

选普通行走、强转弯、近柜台、动态人物、镜面和首尾。对照保持相同源帧、FOV、速度、输出尺寸及测试时段；注明不同标定/缩放的混杂因素。

同时看：
- 画面 roll/水平与高频摆动；
- 中心运动、角速度变化和jerk；
- 上下/左右/近远区域的局部残差和直线弯曲；
- 意图转弯是否被保留、是否新增长周期反向摆动；
- 黑边、接缝、视差、运动模糊和裁切丢内容。

不要只挑好看的窗或只报改善指标。没有不同时间段留出证据时，不把安装轴、曝光offset或读出方向当成精确标定。

## 避开本人和倒影

先明确用户是不出正脸、不出完整人像，还是连手臂也要排除；会话已明确的要求直接沿用。不要因此默认所有顾客都要消失，也不要求用户额外提供自拍做身份识别。

- 优先选择向外镜头/朝向及安全角范围；持续取景变化可能在原本安全的边界引入手臂、反光或另一镜头。
- 原鱼眼→全景、FOV、gyro、水平锁、RS、裁切、zoom任一几何变化后重新测坐标。
- 遮罩声明测量空间、应用阶段、时段、矩形及输入 master SHA256；换master就不能盲用旧绑定。
- 可在几何前遮挡并随图像一起变换，也可在最终master上测后遮挡；不要混用两种坐标。保证强度能覆盖整个反射及运动模糊，不只涂脸部中心。
- 全程稀疏看构图；风险区加密，并单独查遮罩开始前、结束后及重叠切换边界。根据运动速度选择密度，不固定某次任务的15–20秒区间。
- 采用图外时间标签/放大表，不能让标注遮住顶部镜面。技术黑框检查不能代替镜面检查。
- 发现边缘手臂，查看相邻全尺寸帧是否连续连接旁人袖口/身体；无法排除持机者时保守处理，不能凭“看起来像别人”放行。

人像/镜面遮罩坐标、真实视频、导出截图和个体信息属于本次工作产物，不应打包进可复用 skill。

## 字幕和声音

只据用户确认、清晰标识、可复核口述写名称；不能凭相似外观把物件或建筑空间写成另一个名称。模糊标签不猜，嘈杂声的转写文本先复核；明显字幕署名/重复词幻觉不可用于成片。

原声处理避免多代降噪/压缩。AAC packet copy 的源区间、起点、速度必须一致。改变音频、重新编码或重采样后检查有限值、解码峰值、内部缺口/重叠和音画端点；压缩编码仍可能在极少样点产生峰值过载，不能只信编码前 limiter。

### 混音内部时间戳缺口

峰值合格、首尾对齐仍可能隐藏内部音频跳时。曾遇到一个AAC包声明的duration比实际解码样本长，导致后续PTS跳过约50ms；这证明成片包时序有缺口，不足以单独归因于某个滤镜。

定位时记录相邻解码块的 `start = pts × time_base`、`end = start + samples/sample_rate`，连同关联包的PTS/duration核对。不要把整个A/V端点容差当作可接受的内部缺口，也不要把正常AAC尾部padding当内部缺口。

已确认连续混音应无停顿、且问题源于输出时序时，优先从源音轨重建连续PCM。一个经验证的局部修复顺序是：

    ...混音/响度处理...,aresample=<目标采样率>,asetpts=N/SR/TB,apad,atrim=duration=<计划时长>,asetpts=N/SR/TB

先以累计样本重建PTS，再补尾/裁到计划时长；若先按跳变PTS裁切，再重建时间，会保留样本长度不足。保留源材料的真实停顿、偏移和缺失证据，不把此链当所有音频的无条件修复。PCM样本数应与目标时长在采样舍入内一致；重新编码AAC后仍需全程检查连续性、峰值、响度/true peak和端点。有意尾部补静音写进计划，数值合格不等于已听音。

### 仅修音轨时重绑定视频证据

画面本身已合格时，可通过 `-c:v copy` 更换音轨，避免再压视频；不能仅凭命令或相同画面尺寸认定视频未变。

    python3 "$SKILL_DIR/scripts/compare_video_streams.py" --before "$REVIEWED_MASTER" --after "$VIDEO_EXPORT" --report "$VIDEO_WORK/video-identity.json"

要求所选流的非空视频包顺序/数量、长度前缀payload摘要、codec/extradata、有效PTS/DTS/duration及显示元数据一致。时间基不同但有理数归一化后严格相等可接受；缺关键时序或读取能力保留 inconclusive，不据此继承。相同payload但时序、SAR、色彩或旋转显示信息变化，不能直接沿用旧结论；两边同样未声明的标签也不能因此升级为已符合交付合同。

工具同时检查首帧解码前的容器codec参数与解码后的参数，防止SPS信息覆盖容器色彩声明后漏检差异；首帧元数据检查并非完整视频解码。需支持packet side-data读取的PyAV，能力缺失会保留 inconclusive。`--video-stream` 为视频流中的序号，不是容器所有轨道的索引；默认0。该工具用于已探测、可解码的交付文件，陌生多轨源先探测，并用外部作业监督设置时限。

退出码0/1/2分别表示 `exact_video_equivalent` / `different` / `inconclusive`（或输入/报告错误）。重新封装若改变packetization，也可能得到different；这表示未取得严格等价证明，不等于已证明画面损坏。

只有结果为 `exact_video_equivalent`，且原审阅报告绑定原文件/视频证据，才把对应画面检查重新绑定到新文件及比较报告；保留原来的抽帧范围和限制，不能把120帧抽查升级为逐帧人工审阅。新音轨、容器、完整导出合同仍须新验证。输出哈希变更本身不要求重复已证明等价的语义检查。

## 完整导出核验

例如使用本次计划里的变量，不写死30fps或某次帧数：

    python3 "$SKILL_DIR/scripts/verify_export.py" --source "$VIDEO_INPUT" --output "$VIDEO_EXPORT" --expected-frames "$EXPECTED_FRAMES" --fps "$OUTPUT_FPS" --width "$OUTPUT_WIDTH" --height "$OUTPUT_HEIGHT" --report "$VIDEO_WORK/export-check.json" --audio-copy-from "$AUDIO_REFERENCE" --contacts-dir "$VIDEO_WORK/contacts" --privacy-window "$RISK_START:$RISK_END:$RISK_STEP"

--audio-copy-from 只在确实 copy 时加；音频参考需是可正常探测的文件，私有多轨源卡probe时先无损抽出所需音轨。无声技术小样显式使用 --allow-no-audio，不能把它用于应含原声的交付。

按交付计划补充明确期待：--sar（默认1）、--sample-rate、--channels、--color-primaries、--color-trc、--colorspace、--color-range。色彩参数使用 FFmpeg/PyAV 的整数枚举，例如明确要求 SDR BT709/limited 时四项均为1；HDR不能照套。没给的色彩/音频期待会记录为 recorded_not_asserted，不代表匹配已确认。

以读回的容器/帧标签为准，不仅检查编码命令是否写了色彩选项；某些滤镜管线还需在帧上明确 setparams，未声明/未知标签不得按期待值代填。

MP4网页交付可加 --require-faststart；未加时明确 not_checked。音频有限值和解码峰值默认检查，--audio-peak-limit 可按任务配置（默认1.0）；不会把静音本身当成损坏。不要用默认通过状态代替未声明的交付期待。

在最后一次修改后完整运行，核对实际帧数/PTS、fps/尺寸、编码、色彩、容器、faststart、音频连续性及A/V端点、源/输出状态和哈希。黑场/边框是启发式，场景本身黑暗可能触发；检查标记帧并保留人工理由，不偷偷放宽阈值掩盖真黑边。

若只跑metadata-only、抽了几帧或检查未完成，不能称为完整技术通过。即使脚本通过，也必须单独记录人工视觉/隐私审阅范围与残留问题。修改媒体后重新建立文件哈希与检查绑定；视频专属证据只有通过上述等价检查才能按原范围继承，不必无变化反复重跑无关测试。

导出完成与发布/收件确认不同。只有用户另授发布时才进入相应应用；核实当前平台约束和最终服务端状态，不把本地文件完成当发布成功。
